# OmniRAG sample corpus: "Project Aurora"

A small, **entirely fictional** corpus about Helios Energy Lab's sodium-ion battery program. The people, cells, numbers and products are invented for testing.

The facts are deliberately spread across files and formats, so later phases can test multi-hop and cross-document questions. For example:

- *"Which electrolyte replaced the one used in the cell that failed at 45 °C, and who owns its qualification?"* needs the CSV (which cell failed), the meeting notes (the decision) and the JSON config (the owner).
- *"Does the S1 cell's rated cycle life match what the lab measured?"* needs the HTML product page and the CSV.

| File | Format | Contents |
|---|---|---|
| `aurora_research_notes.md` | Markdown | Project overview, chemistry, results table, config snippet |
| `cell_test_results.csv` | CSV | Cycle-test results for cells AUR-C101 … AUR-C108 |
| `aurora_config.json` | JSON | Team, workstreams, test thresholds, milestones |
| `meeting_notes_2026-03-12.txt` | Plain text | Review meeting decisions and action items |
| `helios_aurora_s1.html` | HTML | Product page for the Aurora S1 cell (with nav/footer noise) |
| `aurora_status_report_2026-03.docx` | Word | Monthly report: tracked changes, risk register, figure + caption, lists |
| `aurora_budget_2026.xlsx` | Excel | Budget (percent formats), milestones (dates), offset supplier table, empty sheet |
| `aurora_q1_review.pptx` | PowerPoint | Q1 review: bullets, retention chart, milestone table, picture, speaker notes, hidden slide |
| `aurora_safety_review.pdf` | PDF (born-digital) | Safety review of the AUR-C103 failure: swelling table, figure, recommendations, running header/footer |
| `aurora_lab_notebook_scan.pdf` | PDF (scanned) | One scanned notebook page with **no text layer** (needs OCR) |
| `whiteboard_2026-03-20.jpg` | Image | Phone photo of the E-7 qualification plan, stored sideways with EXIF orientation 6 |
| `e7_technical_note.pdf` | PDF (two-column) | E-7 formulation note: two text columns and a borderless table (routed to Docling) |

More cross-format questions:

- *"How much budget does the electrolyte workstream have, and how much has been spent?"* The Word report gives EUR 240,000 after the extra EUR 85,000; the workbook gives 97,200 spent (40.5%). The deck mentions the approval only in its **speaker notes**.
- *"Do the E-7 cells at 45 °C meet the 80% retention threshold?"* Combine the deck's chart data (89.6% / 90.2% at 600 cycles), the CSV, and the threshold in the JSON config.
- *"How much did AUR-C105 swell, and is that within the limit?"* The scanned notebook (2.1 %, only readable through OCR) and the safety-review PDF table agree. The 5% limit is in the JSON config, on the whiteboard photo and in the Word risk register.

The binary samples are generated by `scripts/make_office_samples.py` and `scripts/make_pdf_samples.py`, but the committed files are the source of truth: regenerating them changes their bytes and therefore their document IDs.
